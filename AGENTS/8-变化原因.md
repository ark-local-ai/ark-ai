# 8 · 变化原因（Agent 架构详解）

> 记录「为什么从 A 变成 B」。区分两种变化：**产品方向调整**（用户要求）与**工程实现调整**（我基于约束做的决策）。每一条都写「原来 / 现在 / 为什么」。

---

## 一、产品方向变化

### 变化 1：侧栏「提示词」入口 → 首页「场景库」（WorkBuddy 式）
- **原来**：侧栏有「提示词」项，对应 `/app/prompts` 平铺提示词列表。
- **现在**：侧栏**移除提示词项**；首页输入台上方做 **6 个场景胶囊**（文档处理/数据分析/…），点开下拉参考提示词，选中后输入台内出现**可移除场景标签** + 回填提示词正文；「全部场景」通向场景库页 `/app/prompts`。
- **为什么**（你的要求）：「舍弃提示词，改为像 WorkBuddy 一样**封装场景**，再根据场景提供对应参考提示词」。核心是从「给一串提示词」变成「让你选场景就能开工」，降低用户写提示词的负担。

### 变化 2：产品的技术阶段
- **原来**：纯前端 + mock 数据（任务步骤动画、假文件）。
- **现在**：接入真实后端（Fastify + SQLite），任务从首页提交 → 后端编排 → SSE 实时推 → 生成真实落盘文件。
- **为什么**（你要做全栈开发）：「我需要你做全栈开发」——把 mock 闭环换成真实后端闭环，打通端到端链路。

## 二、工程实现变化

### 变化 3：数据库 better-sqlite3 → Node 内置 node:sqlite
- **原来**：规划用 better-sqlite3（更快、API 顺手）。
- **现在**：`node:sqlite`（Node 22 内置 `DatabaseSync`）。
- **为什么**：Windows 缺 VS C++ 工具链，better-sqlite3 原生编译失败；内置 SQLite 零编译零依赖，接口几乎一致，符合「本地优先、免构建链」。详见踩坑日志 7-坑1。

### 变化 4：编排先自写状态机，不引 LangGraph
- **原来**：规划文档提到可用 LangGraph。
- **现在**：`orchestrator.ts` 手写步骤循环 + 事件广播。
- **为什么**：里程碑1 用预置计划即可验证链路；避免过早引重框架。预留 `plannerLLM` 接入点，之后无损替换。符合"按需演进"。

### 变化 5：API 创建接口从"等执行完返回"→"秒回 id + 后台异步 + SSE"
- **原来**（初版代码）：`await runTask(...)` 整个编排跑完才返回。
- **现在**：路由层生成 id 立即返回，`void runTask(id, prompt)` 后台跑，进度走 SSE。
- **为什么**：前端要能「秒开任务页 + 实时点亮」；重活异步化才能配合 SSE。详见踩坑日志 7-坑4。

### 变化 6：前端 API 地址用相对路径而非绝对地址
- **原来**：准备写 `http://127.0.0.1:4000`。
- **现在**：`BASE = import.meta.env.VITE_API_BASE ?? ""`（空串 → 相对 `/api/...`）。
- **为什么**：Vite `proxy /api → :4000`，开发零 CORS；生产可由 Fastify 托管静态 + 同源，避免写死端口。

### 变化 7：`steps.note` 列迁移
- **原来**：建表 `steps` 无 `note`。
- **现在**：建表加 `note`，并加「启动检测 column → ALTER 补列」迁移。
- **为什么**：老库已落盘，`IF NOT EXISTS` 不补列，直接 UPDATE 报错。见踩坑日志 7-坑2。

### 变化 8：规划器接入真实 LLM（LLM 优先 + 脚本降级双轨）
- **原来**：orchestrator 里硬编码 4 步预置计划（mock）。
- **现在**：`planner.ts` 先尝试已配置 LLM（openai 兼容 `/chat/completions`）拆 3~6 步 JSON；无渠道 / 失败即降级**场景化脚本计划器**（PPT/Excel/Word/调研关键词各自差异化步骤）。交付文件嵌入规划步骤，`task.model` 标记「LLM/内置计划器」。
- **为什么**：既保证「开箱可跑」（无 key 也能跑通闭环），又配 key 即自动进化成真 Agent 拆解；对前端透明。这是「mock 编排 → 真 Agent」的分水岭。模型渠道当前读环境变量（`ARK_CHANNELS`/`ARK_*`），数据库 CRUD 留待 M6。
