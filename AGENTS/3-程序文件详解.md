# 3 · 程序文件详解（Agent 架构详解）

> 逐个文件讲清楚：它做什么、关键函数/组件、和别的文件怎么协作。按层分层阅读。

## 一、后端 `apps/backend/src/`

### `server.ts` —— 入口
- 用 `buildApp()` 组装 Fastify 实例：注册 CORS、任务路由、成果下载、`/health` 健康检查。
- 底部直接 `listen({ port: 4000, host: "127.0.0.1" })` 启动（只监听本机，符合"数据不出本机"）。
- 成果下载 `GET /api/workspace/*` 用 `createReadStream` 流式返回，并做**目录穿越防护**（`normalize` + `startsWith` 校验）。

### `types.ts` —— 共享类型
- 定义 `Task` / `TaskStep` / `Artifact` / `SseEvent` 等，前后端以同一套字段约定对接（前端 `api.ts` 里的 `TaskDto` 与此对应）。

### `routes/tasks.ts` —— 任务 API
| 方法/路径 | 作用 |
|---|---|
| `POST /api/tasks` | 收 prompt → `randomUUID` 生成 id → **立即返回 `{taskId}`**，后台 `void runTask(id,prompt)` 异步编排 |
| `GET /api/tasks/:id` | 从 SQLite 读任务完整快照返回 |
| `GET /api/tasks/:id/events` | SSE：写 `text/event-stream` 头，订阅事件总线，回放历史 + 心跳防断连 |

> 关键设计：POST 不阻塞等待执行完，先返回 id，进度全靠 SSE —— 前端秒开任务页，步骤实时点亮。

### `agent/orchestrator.ts` —— 编排层（任务闭环大脑）
`runTask(id, prompt)` 流程：
1. 生成任务 → `insertTask` + 逐条 `insertStep`
2. `planTask(prompt)` 拆步骤（见 planner.ts）→ 广播 `plan` 事件 → `updateTaskStatus('running')`
3. 遍历每步：标 `running` → `sleep(900)` 模拟执行 → 最后一步**生成可编辑 Office 文件**（`tools/office.ts` 的 `genOffice`）到 `frontend/public/workspace/` → `insertArtifact`(deliverable) → 广播 `deliver`
4. 逐步置 checks ✓，标 `done`，广播 `check`/`done`
5. 把最终 checks/timeline 写回库 → `getTask` 返回最终快照

> 计划来源：`planner.ts`（LLM 优先 / 无 key 降级脚本计划器），`task.model` 标记「LLM/内置计划器」。

### `agent/planner.ts` —— 任务规划器
- `planTask(prompt)`：先尝试已配置 LLM（openai 兼容）拆 3~6 步 JSON；无渠道/失败降级**场景化脚本计划器**（PPT/Excel/Word/调研各自差异化步骤）。
- 返回 `{ steps, viaLLM }`，orchestrator 据此标记模型来源。

### `tools/office.ts` —— Office 文件生成
- `detectKind(prompt)`：按关键词选 PPT/Excel/Word。
- `genOffice(prompt, steps, outDir)`：用 pptxgenjs / exceljs / docx 生成**可编辑真实文件**并落盘，返回 `{name, kind, path}`。
- Excel 含原生公式（`COUNTA` 统计），PPT/Word 文字可编辑 —— 兑现"交付可编辑文件"卖点。

### `config/channels.ts` + `models/client.ts` —— 模型渠道
- `channels.ts`：读 `ARK_CHANNELS` / `ARK_*` 环境变量的渠道配置，`getDefaultChannel()` 取默认。
- `client.ts`：openai 兼容适配器，零依赖 fetch 调 `/chat/completions`，供 planner 拆步骤用。

### `models/router.ts` —— 模型路由
- `pickChannel()`：按各渠道**成功率**选最优（无记录按可用，有成功记录优先）。
- `recordSuccess/Failure(id)`：写 SQLite `channel_stats`，进程重启不丢。
- `getChannelStats()`：供 `GET /api/channels` 展示渠道 + 成功率。

### `agent/verifier.ts` —— 验收/重试
- `verifyDeliverable(path, kind)`：校验交付文件真实有效（存在 / 非空 / Office zip `PK` 头）。
- `verifyWithRetry(gen, maxTimes)`：生成后校验，不达标限次重试（最多 3 次），超限抛错。

### `tools/workspace.ts` —— 工作空间真扫描
- `scanWorkspace(dir)`：`readdirSync` + `statSync` 扫真实目录，返回文件列表（name/kind/size/sizeText/time，按大小倒序）。kind 由扩展名映射（pptx→ppt、xlsx→xls、docx→doc、md→md、png→png、html→html、pdf→pdf）。
- 供 `GET /api/workspace`（列目录）与下载联动；目录不存在时安全返回 `[]`。

### `routes/channels.ts` —— 渠道 API
- `GET /api/channels`：返回渠道列表 + ok/fail/rate 成功率统计（供前端设置页展示）。

### `routes/chat.ts` —— 对话 API
- `POST /api/chat`：SSE 逐 token 推送。有模型渠道 → 真实 LLM `chatStream` 流式；无 key/失败 → 内置回复逐字流式降级（`event: token`… 最后 `event: done`）。
- 前端 `sendChat()` 逐 token 渲染 + 流结束把完整回复沉淀进 history（多轮上下文）。

### `models/client.ts` —— openai 兼容 client
- `chat()`：非流式单轮补全。
- `chatStream()`：流式补全（`stream:true`），逐 `delta.content` 回调 `onDelta`，兼容 Ollama SSE 协议。供 chat 路由用。

### `agent/events.ts` —— 事件总线
- `subscribe(taskId, send)`：注册 SSE 发送器；返回取消函数。支持**回放**：新订阅者立即收到已发生事件。
- `publish(event)`：给该任务所有订阅者广播，并写入 `replay` 缓存。

### `db/store.ts` —— SQLite 存储层
- 用 Node 内置 `node:sqlite` 的 `DatabaseSync`。
- 建 3 张表：`tasks` / `steps` / `artifacts`。
- 提供：`insertTask/getTask/insertStep/updateStepStatus/updateTaskStatus/insertArtifact/updateTaskChecksAndTimeline`。
- 含**迁移逻辑**：检测老库缺 `steps.note` 列就 `ALTER TABLE` 补列（踩坑见 7）。

## 二、前端 `apps/frontend/src/`

### `api.ts` —— 前端 API 客户端（本次新增）
- `createTask(prompt)` → POST，返回 `taskId`
- `getTask(id)` → GET 快照
- `subscribeTask(id, handler)` → 用 `EventSource` 订阅，按事件类型分发到回调，返回 `es.close()` 取消函数
- `workspaceUrl(name)` → 拼下载 URL
- `BASE` 默认空串（走 Vite 代理），可用 `VITE_API_BASE` 覆盖

### `pages/Home.tsx` —— 新会话首页（场景库入口）
- 顶部 6 个**场景胶囊**（文档处理/文档写作/数据分析/演示文稿/深度调研/会议纪要）+「全部场景」。
- 点胶囊展开下拉（`chip-menu`）列出该场景参考提示词，选中后 `applyPrompt(scene, prompt)`：设置标签 + 回填输入框。
- 输入框为**受控组件**（`v` 来自 `onChange`），提交 `POST /api/tasks` → 成功后 `nav("/app/task?taskId=...")`。
- 从场景库跳回时读取 `location.state.{scene,prompt}` 预填。

### `pages/TaskPage.tsx` —— 任务执行页（本次改为接真实 API）
- 读 URL `?taskId=`。
- `useEffect`1：`getTask` 拉取**真实任务快照**打底。
- `useEffect`2：`subscribeTask` 订阅 SSE，处理 `plan`（初始化步骤）/`step`（点亮）/`deliver`（出现交付卡）/`check`（勾选清单）/`done`。
- 渲染：步骤条（done✓/running●/wait）、交付成果卡（下载按钮跳 `workspaceUrl`）、右侧验收清单 + 配置 + 时间线。
- 任务不存在/后端未启动 → 显示空态提示。

### `data/mock.ts` —— 静态数据（部分仍为 mock，部分已被 API 替代）
- 新增 `Scenario` / `ScenePrompt` 类型 + `scenarios`（6 场景 15 条提示词）。
- `Task` 等类型仍用于静态示例（TaskPage 已改用 `api.ts` 的 `TaskDto`，不再强依赖 mock task）。

### 设计系统
- `index.css`：暖米白/茶褐设计令牌（`--bg` `--surface` `--brand` 等）。
- `shell.css`：应用壳（侧栏/顶栏/首页动画）+ 场景胶囊下拉 + 输入台标签样式。
- `pages/pages.css`：各页面（含场景库）样式。
- `layout/Sidebar.tsx` + `Layout.tsx`：应用壳导航与路由标题。

## 三、文件协作图（一次任务的生命周期穿越的文件）

```
Home.tsx ──applyPrompt/v──▶ submit() ──createTask──▶ api.ts ──POST──▶ routes/tasks.ts
                                                                    │ runTask(id,prompt)
                                                                    ▼
                                          agent/orchestrator.ts ──▶ events.ts (广播)
                                              │ 落库                │
                                              ▼                    ▼
                                          db/store.ts (SQLite)   SSE 写回
                                                                   │
TaskPage.tsx ◀──subscribeTask── api.ts ◀──GET/events── routes/tasks.ts
     │ getTask(id) 快照 ◀──── db/store.ts
```
