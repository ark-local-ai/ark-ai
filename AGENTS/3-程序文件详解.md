# 3 · 程序文件详解（Agent 架构详解）

> 逐个文件讲清楚：它做什么、关键函数/组件、和别的文件怎么协作。按层分层阅读。

---

## 一、后端 `apps/backend/src/`

### `server.ts` —— 入口
- 用 `buildApp()` 组装 Fastify 实例：注册 CORS、任务路由、成果下载、`/health` 健康检查。
- 底部直接 `listen({ port: 4000, host: "127.0.0.1" })` 启动（只监听本机，符合"数据不出本机"）。
- 成果下载 `GET /api/workspace/*` 用 `createReadStream` 流式返回，并做**目录穿越防护**（`normalize` + `startsWith` 校验）。

### `types.ts` —— 共享类型
- 定义 `Task` / `TaskStep` / `Artifact` / `SseEvent` 等，前后端以同一套字段约定对接（前端 `api.ts` 里的 `TaskDto` 与此对应）。

### `routes/tasks.ts` —— 任务 API
| 方法/路径 | 作用 |
|---|---|
| `POST /api/tasks` | 收 prompt → `randomUUID` 生成 id → **立即返回 `{taskId}`**，后台 `void runTask(id,prompt)` 异步编排 |
| `GET /api/tasks/:id` | 从 SQLite 读任务完整快照返回 |
| `GET /api/tasks/:id/events` | SSE：写 `text/event-stream` 头，订阅事件总线，回放历史 + 心跳防断连 |

> 关键设计：POST 不阻塞等待执行完，先返回 id，进度全靠 SSE —— 前端秒开任务页，步骤实时点亮。

### `agent/orchestrator.ts` —— 编排层（任务闭环大脑）
`runTask(id, prompt)` 流程：
1. 生成任务 → `insertTask` + 逐条 `insertStep`
2. `planTask(prompt)` 拆步骤（见 planner.ts）→ 广播 `plan` 事件 → `updateTaskStatus('running')`
3. 遍历每步：标 `running` → `sleep(900)` 模拟执行 → 最后一步**生成可编辑 Office 文件**（`tools/office.ts` 的 `genOffice`）到 `frontend/public/workspace/` → `insertArtifact`(deliverable) → 广播 `deliver`
4. 逐步置 checks ✓，标 `done`，广播 `check`/`done`
5. 把最终 checks/timeline 写回库 → `getTask` 返回最终快照
- **M31 断点续跑**：`runTask`（全新）与 `resumeTask`（重启恢复）共用内部 `runPlanSteps` 循环（startIdx + sections 注入）——每步置 done 时把产出整篇持久化进 `steps.note`；`resumeTask` 读已持久化步骤、把已完成步的产出接回 sections、从第一个未完成步续跑（不 reset），末步重新生成交付。

> 计划来源：`planner.ts`（LLM 优先 / 无 key 降级脚本计划器），`task.model` 标记「LLM/内置计划器」。

### `agent/planner.ts` —— 任务规划器
- `planTask(prompt)`：先尝试已配置 LLM（openai 兼容）拆 3~6 步 JSON；无渠道/失败降级**场景化脚本计划器**（PPT/Excel/Word/调研各自差异化步骤）。
- 返回 `{ steps, viaLLM }`，orchestrator 据此标记模型来源。

### `tools/office.ts` —— Office 文件生成
- `detectKind(prompt)`：按关键词选 PPT/Excel/Word。
- `genOffice(prompt, steps, outDir)`：用 pptxgenjs / exceljs / docx 生成**可编辑真实文件**并落盘，返回 `{name, kind, path}`。
- Excel 含原生公式（`COUNTA` 统计），PPT/Word 文字可编辑 —— 兑现"交付可编辑文件"卖点。

### `config/channels.ts` + `models/client.ts` —— 模型渠道
- `channels.ts`：**DB 持久化渠道**（SQLite `channels` 表），首启用内置 6 渠道/env 引导种子；`getChannels/getChannelById/getDefaultChannel` 读 DB；`createChannel/updateChannel/deleteChannel/setDefaultChannel` CRUD。
- `client.ts`：openai 兼容适配器，零依赖 fetch 调 `/chat/completions`（含 `chatStream` 流式），供 planner / chat 用。

### `models/router.ts` —— 模型路由
- `pickChannel()`：按各渠道**成功率**选最优（无记录按可用，有成功记录优先）。
- `recordSuccess/Failure(id)`：写 SQLite `channel_stats`，进程重启不丢。
- `getChannelStats()`：供 `GET /api/channels` 展示渠道 + 成功率。

### `agent/verifier.ts` —— 验收/重试
- `verifyDeliverable(path, kind)`：校验交付文件真实有效（存在 / 非空 / Office zip `PK` 头）。
- `verifyWithRetry(gen, maxTimes)`：生成后校验，不达标限次重试（最多 3 次），超限抛错。

### `tools/workspace.ts` —— 工作空间真扫描
- `scanWorkspace(dir)`：`readdirSync` + `statSync` 扫真实目录，返回文件列表（name/kind/size/sizeText/time，按大小倒序）。kind 由扩展名映射（pptx→ppt、xlsx→xls、docx→doc、md→md、png→png、html→html、pdf→pdf）。
- 供 `GET /api/workspace`（列目录）与下载联动；目录不存在时安全返回 `[]`。

### `tools/skills.ts` —— 技能管理（Markdown 即技能，落盘热加载）
- 每个技能一个 `<id>.md`，元信息（name/desc/enabled）写在开头 HTML 注释 front-matter；改文件即生效。
- `ensureSeed`（空目录写内置 5 技能）、`listSkills`（扫描解析）、`getSkill`、`writeSkillMeta`（整写回）、`toggleSkill`、`saveSkill`。
- 供 `GET/PUT /api/skills`、`/toggle`；**重启持久**（历史编辑保留）。

### `routes/skills.ts` —— 技能 API
- `GET /api/skills` 列表；`GET /api/skills/:id` 含 code；`PUT /api/skills/:id` `{name,desc,enabled,code}` 保存；`POST /api/skills/:id/toggle` `{enabled}`。

### `data/experts.ts` + `routes/experts.ts` —— 专家目录
- 内置 5 位专家（静态数据，后续可 CRUD），`GET /api/experts` 返回。

### `scheduler/jobs.ts` —— 自动化定时任务（本地 Cron）
- `jobs` / `job_logs` 两张 SQLite 表；CRUD（list/get/create/update/delete）+ `addLog`。
- `runJob(id)`：调 `runTask` 执行 action（复用编排闭环）产出真实文件并记成功/失败日志。
- `startScheduler()`：每 30s 轮询，`isDue` 匹配「每天 HH:MM 或 every:N 分钟」且启用 → 触发，同分钟防重。
- `describeSchedule`：把 schedule 转成可读「下次执行」文案。

### `routes/jobs.ts` —— 定时任务 API
- `GET /api/jobs` 列表；`POST` 新建；`PUT /:id`；`DELETE /:id`；`POST /:id/run` 手动执行；`GET /api/jobs/logs` 执行历史。

### `routes/connectors.ts` —— 连接器状态 API
- `GET /api/connectors`：真实状态。模型渠道（读 DB 报「N 个渠道·默认 X」）；Ollama 本地（`probeOllama` 真探 `GET localhost:11434/api/tags` 判在线）；联网搜索/内置浏览器/IM 桥（未接入，如实标未接入）。

### `routes/scenarios.ts` + `data/scenarios.ts` —— 场景库（WorkBuddy 式）
- `GET /api/scenarios`：返回 6 个场景 + 参考提示词。首页场景胶囊与提示词库页共用；前端 `listScenarios` 拉取（mock 仅离线降级）。

### `routes/channels.ts` —— 渠道 API
- `GET /api/channels`：渠道列表 + baseUrl + ok/fail/rate 成功率统计。
- `POST` 新增；`PUT /:id` 编辑；`DELETE /:id`；`POST /:id/default` 设默认；`POST /:id/test` 验活（GET `{baseUrl}/models` 判连通）。

### `routes/chat.ts` —— 对话 API
- `POST /api/chat`：SSE 逐 token 推送。有模型渠道 → 真实 LLM `chatStream` 流式；无 key/失败 → 内置回复逐字流式降级（`event: token`… 最后 `event: done`）。
- 前端 `sendChat()` 逐 token 渲染 + 流结束把完整回复沉淀进 history（多轮上下文）。

### `models/client.ts` —— openai 兼容 client
- `chat()`：非流式单轮补全。
- `chatStream()`：流式补全（`stream:true`），逐 `delta.content` 回调 `onDelta`，兼容 Ollama SSE 协议。供 chat 路由用。

### `agent/events.ts` —— 事件总线
- `subscribe(taskId, send)`：注册 SSE 发送器；返回取消函数。支持**回放**：新订阅者立即收到已发生事件。
- `publish(event)`：给该任务所有订阅者广播，并写入 `replay` 缓存。

### `db/store.ts` —— SQLite 存储层
- 用 Node 内置 `node:sqlite` 的 `DatabaseSync`；DB 路径可用 `ARK_DB_PATH` 覆盖（M25 起测试隔离用）。
- **表**：`tasks` / `steps` / `artifacts` / `spaces`（多工作空间 M11）/ `users`+`sessions`（登录 M12）/ `chat_sessions`+`chat_messages`（对话持久化 M19）/ `chat_messages_fts`（对话全文搜索 M23）/ `audit_log`（操作审计 M29）。
- **任务**：`insertTask`（含 `user_id`/`archived` 持久化）/`getTask`/`insertStep`/`updateStepStatus`/`updateTaskStatus`/`insertArtifact`/`updateTaskChecksAndTimeline`/`resetTask`（幂等复位，供重试 M17）/`deleteTask`/`setTaskArchived`（归档 M22）/`listTasks`（多用户隔离 + 活跃/归档过滤）/`getUnfinishedTasks`（进程重启恢复 M24）/`countTasksByStatus`（统计 M18）/`recentTasks`。
- **对话**：`createChatSession`/`appendChatMessage`（同步入 FTS 索引）/`listChatSessions`/`getChatMessages`/`deleteChatSession`/`searchChatMessages`（FTS，按会话去重）/`reindexChats`（启动重建索引）。
- **空间/用户/会话**：`listSpaces/createSpace/updateSpace/deleteSpace/getActiveSpace`；`createUser/findUserByUsername/verifyPassword/hashPassword`（scrypt）；`createSession/resolveSession/destroySession/pruneSessions`。
- **审计（M29）**：`appendAudit`（写一条，fire-and-forget）/`listAudit`（倒序可 limit）/`clearAudit`。
- **迁移逻辑**：`PRAGMA table_info` 检测缺列就 `ALTER TABLE` 补列（`steps.note`、`tasks.user_id`、`tasks.archived`、`spaces.user_id`、`channel_stats.latency_*`），幂等。

### `agent/events.ts` —— 事件总线（M21 起支持全局）
- `subscribe(taskId, send)`：注册 SSE 发送器，返回取消函数；支持**回放**（新订阅者立即收到已发生事件）。
- `subscribeAll(send)`（M21）：订阅**所有任务**的事件流，用于全局 SSE `/api/events`（任意页通知 + 侧栏刷新）。
- `publish(event)`：给该任务订阅者 + 全局订阅者广播，写 `replay` 缓存。

### `agent/runner.ts` —— 受控并发队列 + 失败兜底（M16）+ 重启恢复（M24）＋ 并发控制（M30）
- `enqueueTask(id, prompt, userId)`：**信号量槽位**受控并发（默认同跑 2，`ARK_MAX_CONCURRENCY` 覆盖），FIFO 排队；`getQueueStats()` 返回 `{active,queued,concurrency}`。
- `execute` 内 try/catch 包整个 `runTask`：任何异常 → `updateTaskStatus('failed')` + 广播 SSE `error`，不再卡 running。
- `resumeUnfinishedTasks()`（M24）：启动时把 `getUnfinishedTasks()` 命中的遗留 queue/running 任务重新入队；M31 起走 `enqueueResume` → `resumeTask`（断点续跑，不再从头重跑）。

### `agent/pipeline.ts` —— 多 Agent 内容管线（M10b）
- 分析师（提炼要点）→ 写手（展开 sections）→ 校验（收尾/补结论）三角色顺序执行，各 Agent 独立 LLM 优先 + 确定性脚本降级（20s 超时）。
- orchestrator 最后一步调 `runContentPipeline`，交付内容来自此管线；取代被删的 `llmContent.ts`。

### `tools/registry.ts` —— 工具注册表（M10）
- 统一接口 `{name, describe, run}`；`defaultTool` 内容整编工具。新工具=注册一个实现。
- orchestrator 每步经 Tool Registry 产出该步内容，注入最终 Office 交付。

### `tools/searchIndex.ts` —— 工作空间全文搜索（M20）
- `workspace_files`（文件名元数据）+ `workspace_files_fts`（FTS5 **trigram**）索引；`reindexWorkspace()` 启动时重建；`searchWorkspaceFiles(q)` 子串命中。
- 供 `GET /api/workspace/search`（必须在 `/api/workspace/*` 通配前注册）与 Sidebar Cmd+K。

### `util/log.ts` —— 结构化日志（M26）
- pino 配置 `base:{service:"ark-backend"}` + `enabled:!ARK_TEST`；导出 `loggerOptions`（给 Fastify 的配置对象）与 `taskLogger(taskId)`（任务执行用，taskId 作贯穿键）。
- orchestrator/runner 打点（task started/deliverable/finished/executionStarted/failed）。

### `models/router.ts` —— 模型路由（M14 起 failover + M15 加权 + M27 熔断）
- `pickChannel()` / `orderedChannels()`：按综合评分选优（可靠性50%+延迟20%+成本15%+优先级15%），**跳过被熔断渠道**。
- `recordSuccess/Failure/Latency(id)`：写 SQLite `channel_stats`；失败同时喂熔断计数。
- `isChannelOpen(id)`（M27）：连续失败 5 次 open + 10s cooldown + half-open 探测。
- `chatWithFailover(messages)`：按评分排序**逐个尝试所有渠道**直到成功，全败才抛错（上层降级）。
- `getChannelStats()`：供 `GET /api/channels` 展示渠道 + 成功率 + 延迟 + 评分。

### `routes/scenarios.ts` + `data/scenarios.ts` —— 场景库（WorkBuddy 式）
- `GET /api/scenarios`：返回 6 个场景 + 参考提示词。首页场景胶囊与提示词库页共用；前端 `listScenarios` 拉取（mock 仅离线降级）。

### `routes/auth.ts` —— 登录/注册 API（M12，软门禁）
- `POST /register` / `POST /login` / `POST /logout` / `GET /me` / `GET /status`（hasUsers+me）。密码 scrypt 哈希、session token 存 DB 7 天。
- `currentUser(req)`：读 Bearer token 解析当前用户，供任务/空间路由做资源隔离（传 user_id 过滤）。

### `routes/stats.ts` —— 统计仪表盘 API（M18）
- `GET /api/stats`：任务状态计数 + 最近任务 + 渠道健康（均值/最优评分），供前端 `/app/stats`。

### `routes/chat-sessions.ts` —— 对话会话 API（M19）
- `GET /api/chat/sessions` / `GET .../:id/messages` / `DELETE .../:id`，供侧栏会话栏与 `?sess=` 恢复。

### `routes/events.ts` —— 全局事件流 API（M21）
- `GET /api/events`：subscribeAll 订阅，把所有任务事件以 SSE 帧广播（15s 心跳），供任意页通知 + 侧栏刷新。

### `routes/audit.ts` —— 操作审计 API（M29）
- `GET /api/audit`：查看最近审计日志（倒序，可 `?limit=`，默认 200 上限 1000）。
- **根 onResponse 钩子**（导出 `installAuditHook`，在 server 根上下文按装）：统一审计所有 POST/PUT/DELETE 到 `/api/*` 的写请求——`currentUser` 归到当前用户（未登录记匿名），method+url → 可读中文动作 + 目标 id，写 `audit_log`。写请求无论成败都记（防抵赖）。**坑**：onResponse 是封装的，装在带 prefix 的插件里只审自己的路由，必须根上下文装（见 7-踩坑12）。

### `routes/queue.ts` —— 任务队列状态 API（M30）
- `GET /api/queue`：返回执行队列实时状态 `{active, queued, concurrency}`——正在执行 / 排队等待 / 配置并发上限（读 `getQueueStats()`）。供统计页/观测展示并发压测与排队情况。

### `maintenance/cleanup.ts` —— 自动清理（M32）
- `runCleanup()`：**按龄清理**终态(done/failed)非归档任务及其交付文件 + **审计裁剪**。取 `getCleanableTaskIds(olderThan)`（`tasks.created_ts < olderThan`，不碰 running/queue/归档）→ `listDeliverableFiles` 得交付文件名 → `safeUnlink`（只删工作目录内、防遍历穿越）→ 逐个 `deleteTask`；`audit_log` 超 `AUDIT_MAX` 则 `pruneAudit` 裁掉最旧。env 可配 `ARK_CLEANUP_ENABLED/TASK_DAYS/AUDIT_MAX`。返回汇总 `{enabled,tasksDeleted,filesDeleted,auditPruned,...}`。
- `routes/maintenance.ts`：`POST /api/maintenance/cleanup` 手动触发一次清理。

### `routes/templates.ts` —— 任务模板 API（M33）
- `GET /api/templates` 列表（多用户隔离：自己的+全局）、`GET /:id` 详情、`POST /` 创建、`PUT /:id` 更新、`DELETE /:id` 删除。
- `POST /:id/run`：**一键应用模板建任务**——取模板 prompt 经 `enqueueTask` 入队开始执行（与首页建任务同一条管线），返回 `{taskId}`。写请求自动落审计（应用任务模板/创建/编辑/删除任务模板）。
- 前端 `/app/templates` 页（`pages/Templates.tsx`）：列表 + 新建/编辑表单 + 删除 + 「应用并执行」按钮。

### `routes/tasks.ts` —— 任务 API（M17 起含生命周期）
| 方法/路径 | 作用 |
|---|---|
| `POST /api/tasks` | 收 prompt → id → **立即返回**，`enqueueTask` 入队后台串行执行 |
| `GET /api/tasks` | 列表摘要（`?archived=1` 只列归档，多用户隔离） |
| `GET /api/tasks/:id` | 完整快照 |
| `GET /api/tasks/:id/events` | SSE 回放 + 心跳 |
| `POST /api/tasks/:id/retry` | 失败/完成任务用原 prompt 重新入队（幂等复位） |
| `DELETE /api/tasks/:id` | 删任务含步骤/产物 |
| `POST /api/tasks/:id/archive` | 归档/取消归档（运行中 409） |
| `POST /api/tasks/:id/template` | 另存为模板：done 任务一键固化为模板（继承 prompt/expert/skills/model，M34） |

> 关键设计：POST 不阻塞等待执行完，先返回 id，进度全靠 SSE —— 前端秒开任务页，步骤实时点亮。M16 起用 `enqueueTask` 受控并发队列（M30 起信号量，非直接 `runTask`）。

## 二、前端 `apps/frontend/src/`

### `api.ts` —— 前端 API 客户端
- 任务：`createTask(prompt)`→POST 返回 taskId；`getTask(id)` 快照；`listTasks(archivedOnly)` 摘要；`retryTask/deleteTask/setTaskArchived`（M17/M22）。
- 流式：`subscribeTask(id, handler)`（EventSource 按事件类型分发）；`subscribeGlobal(onEvent)`（M21 全局事件，任意页通知用）。
- 认证：`getToken/setToken`、`authHeaders()`（已登录则带 Bearer，资源按用户隔离）、`register/login/logout/getAuthStatus`（M12）。
- 空间/文件：`listSpaces/createSpace/deleteSpace/setActiveSpace/listSpaceFiles`；`searchWorkspace(q)`（M20 FTS）。
- 对话：`listChatSessions/getChatMessages/deleteChatSession`（M19）、`searchChatMessages(q)`（M23）。
- 统计：`getStats()`（M18）。
- `BASE` 默认空串（走 Vite 代理 `/api`→4000），可用 `VITE_API_BASE` 覆盖。

### `layout/Sidebar.tsx` —— 侧栏（聚合导航 + 最近任务 + 全局搜索）
- 空间视图（M11 真实空间 CRUD）+ 最近任务（M9 接真，M21 起 done/error 自动刷新，M22 归档切换/右键菜单）+ 用户区（M12 登录弹窗）。
- **Cmd+K 全局搜索**：任务 + 工作空间文件（M20）+ 历史对话（M23），弹板分三区。

### `pages/Home.tsx` —— 新会话首页（场景库入口）
- 顶部 6 个**场景胶囊** +「全部场景」；点开下拉列参考提示词，选中 `applyPrompt` 回填输入台（可移除标签）。
