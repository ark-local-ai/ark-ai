# 5 · 企业级演进路线（Agent 架构详解）

> 从「本地单机原型」演进到「企业级多用户」的分阶段路线。每阶段说清：动机、改什么、风险。当前处于**阶段 0（单机闭环已通）**。

---

## 阶段 0 · 单机全栈闭环（当前）
- **现状**：React 前端 + Fastify 后端 + 单机 SQLite；任务 mock 编排 + md 文件交付；SSE 实时进度。
- **价值**：验证「一句话 → 拆步骤 → 执行 → 交付可编辑文件」的核心主张，全链路跑通。
- **局限**：编排是假计划、无真实 LLM、只产 md、数据单机、用户单账号。

---

## 阶段 1 · 接真实智能（价值跃迁）
**动机**：让"拆步骤/执行/验收"由真模型驱动，而非硬编码。

- [ ] **接 LLM**：openai 兼容 SDK（DeepSeek/GLM/Kimi，渠道已在 mock）+ Ollama。`plannerLLM(prompt) => Step[]` 替换硬编码计划。
- [ ] **工具执行**：联网搜索、文件读写、**Office 生成**（pptxgenjs / exceljs / docx）——交付从 md 升级为 pptx/xlsx/docx。
- [ ] **模型渠道管理**：设置页把 mock channels 接成真 CRUD + 验活 + 路由。
- **风险**：LLM 输出不可控 → 需自检验收 + 失败重试（编排层已预留 `failed` 状态）。
- **架构影响**：小而局部，`orchestrator` 内部扩展，不影响 API 形状。

---

## 阶段 2 · 多用户 / 鉴权 / 数据分离
**动机**：从"一个本机工作台"变成"团队可用"。

- [ ] 账号体系（JWT/session）+ 用户 → 任务归属
- [ ] 多工作空间隔离（每个用户/项目独立空间与文件）
- [ ] 数据表加 `owner_id`；文件按用户分目录
- **架构影响**：DB schema、鉴权中间件、文件存储路径管理。

---

## 阶段 3 · 分布式 / 高可用
**动机**：多实例、任务量大、不丢事件。

- [ ] SQLite → **PostgreSQL**（`node:sqlite` 是单机；分布需真库 + 连接池）
- [ ] 事件总线内存 Map → **Redis pub/sub** 或消息队列（多实例共享进度广播）
- [ ] 任务编排可重试/可恢复（进程重启后从 DB 重建未完成任务）
- [ ] 队列化任务（BullMQ / 轻量自己的队列）
- **风险**：基础设施复杂度上升，与"本地优先"拧巴 → 应做「可剥离」设计：本地仍是单机 SQLite，企业部署才上 PG。

---

## 阶段 4 · 桌面 + IM 触达（回到产品主张）
**动机**：产品定位是「本地优先 + 数据不出机 + 随时派活」。

- [ ] **Tauri 2 桌面壳**（复用前端；Rust 后端可访问本地文件）
- [ ] **IM 桥**（企业微信/飞书/QQ）：外出发消息指挥本机干活，干完推回文件——文档里的"远程派活"落点
- [ ] 记忆 / 内置浏览器（真渲染+表单填写）
- **架构影响**：新增 IM 网关层；桌面用 Tauri 命令替代/并行 HTTP。

---

## 演进原则（贯穿始终）

1. **可剥离**：本地单机（SQLite/SSE/自写状态机）与企业级（PG/Redis/队列）做成可平滑切换，不捆绑。
2. **类型共享**：前后端共享 TS 类型契约，接口演进有编译期校验。
3. **每个里程碑独立可验收**：像搭积木，每块做完能跑能看。
4. **数据不出本的底线**：默认只监听 127.0.0.1；任何接外功能（IM、联网）需显式开启并提示。

---

## 路线时间盒（建议）

| 阶段 | 建议周期 | 关键产出 |
|---|---|---|
| 阶段1 真智能 | 1-2 周 | 真 LLM + pptx/xlsx 交付 |
| 阶段2 多用户 | 1 周 | 登录 + 数据隔离 |
| 阶段3 高可用 | 2-3 周 | PG + 队列 + 恢复 |
| 阶段4 桌面+IM | 2-3 周 | Tauri 壳 + IM 桥 |
