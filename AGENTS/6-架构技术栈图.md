## 二、技术栈清单与「为什么」（核心决策）

| 层 | 选型 | 为什么（一句话） |
|---|---|---|
| 前端框架 | React 19 + TS | 生态成熟、组件化；TS 全链路类型安全 |
| 前端构建 | Vite | 极快、现代 ESM；dev proxy 天然代理 `/api` |
| 前端样式 | 手写 CSS 设计令牌 | 遵循设计系统（暖米白 + 暖茶褐，禁蓝），克制统一 |
| 后端 HTTP | Fastify | 性能好、自带 schema 校验、对 SSE/流式友好；比 Express 强、比 Nest 轻 |
| 数据库 | Node 内置 `node:sqlite` | 零依赖零编译（免 node-gyp），同步 API 简单，契合"本地优先" |
| Agent 编排 | 自写状态机 | 先跑通闭环，留 `plannerLLM` 接入点；按需演进不炫技 |
| LLM | openai 兼容 fetch | 统一多家协议（DeepSeek/OpenAI/Ollama→ollama 也兼容），零依赖 |
| 进度推送 | SSE（非 WebSocket） | 服务器单向持续推送，SSE 足够且更轻；带 replay 缓存不丢进度 |

## 三、核心数据流（一句话闭环）

```
首页输入 → POST /api/tasks → planner 拆步骤(LLM/降级) → orchestrator 逐步执行
  每一步状态先落库 → 再 SSE 广播 → 前端实时点亮
  最后生成真实文件到 workspace → deliver 事件 → 前端可下载
全程仅监听 127.0.0.1，数据不出本机
```

## 四、当前运行方式

```bash
# 后端（apps/backend）
npm run dev            # tsx watch src/server.ts，127.0.0.1:4000

# 前端（apps/frontend）
npm run dev            # Vite 5173，/api 代理到后端
open http://localhost:5173/app   # 进工作台，输入需求提交
```
